# 通用蒸馏方法

## 定义

这里的“蒸馏”不是教师模型训练学生模型，也不涉及微调、LoRA 或权重更新。它是一个智能体工作流：把代码、页面、交互、图像、音视频、文章、书籍、课程或混合素材压缩为带证据的规律画像，再把画像迁移到新任务并验收。

完整链路是：

```text
原始来源 → 确定性证据 → 语义事实卡 → 聚合画像 → 再生成契约 → 新候选 → 同路线复测 → 验收
```

摘要只回答“来源说了什么”；蒸馏还必须回答“什么机制反复成立、在什么条件下成立、如何迁移、怎样判定做到了”。

## 先确定画像层级

- 单个仓库、页面、作品或课程只能形成“对象配方”。
- 多个独立样本可以形成作者、创作者、品牌、产品或方法画像。
- 同一个文件的切片、转载、镜像和模板变体不算独立支持来源。
- 来源混合时，只有描述同一对象或服务同一目标才建立统一画像；否则分别建画像。

脚本的频率分类只是候选。题材、平台、时期、栏目、协作者和工具限制都可能制造伪稳定规律，必须由宿主复核。

## 状态语义

| 状态 | 含义 |
| --- | --- |
| `extraction_status` | 文件、文本、帧、声音或结构是否成功提取。 |
| `evidence_ready` | 已形成可复核证据，尚未完成语义蒸馏。 |
| `draft` | 自动聚合画像，仍有冲突和媒介契约待处理。 |
| `reviewed` | 宿主核对证据、变量、边界和契约后的画像。 |
| `complete` | 当前模式的所有强制质量门通过。 |

解析器中的 `status=complete` 只受 `status_scope` 约束，不能改写成“蒸馏完成”。

## 标准闭环

### 1. 定义任务

记录来源范围、目标画像、使用场景、输出媒介以及模式：

- `faithful`：授权范围内忠实重建当前对象。
- `transfer`：保留机制，替换主题、事实、主体、文案和专属资产。

### 2. 建立证据

使用来源对应分析器。网站、App、UI 或无法由通用脚本直接操作的来源，由宿主实际浏览/操作后保存截图、录屏、导出和观察日志，再登记：

```bash
python scripts/kunpeng.py host-evidence <采集目录> --source-type <website|app|ui|brand|repository|course|mixed|other> --source-label "名称" --output <证据目录>
```

证据必须能定位到页码、段落、时间码、镜头、画面区域、页面状态、文件与符号或其他可复查位置。

### 3. 清理来源

- 文本去重、识别转载、页眉页脚和模板段落。
- 仓库排除依赖、构建物、生成文件和废弃分支。
- 视觉和视频区分同图裁切、同片拆段、系列模板与独立作品。
- 网站记录登录、权限、地区、设备、视口和版本造成的覆盖限制。
- 保留纳入、排除和异常理由；被排除来源填写 `review_status=excluded` 的卡，不能静默丢弃或抬高支持度。

### 4. 建事实卡

```bash
python scripts/kunpeng.py prepare-review <一个或多个manifest.json> --output <复核目录>
```

宿主按 `review-tasks.json` 实际查看来源并填写 `cards/*.json`。每条模式必须包含稳定 key、陈述、机制、触发条件、边界、参数、置信度和证据定位。只写“高级、克制、电影感、用户友好”不算规律。

### 5. 聚合画像

```bash
python scripts/kunpeng.py build-profile <复核目录/cards> --output <profile.draft.json>
```

逐项处理：

1. 合并真正同义的 key，拆开同名异义模式。
2. 核对支持来源是否独立。
3. 把主题/平台/阶段造成的特征移到变量或条件规律。
4. 保存矛盾、例外、成本和失效条件。
5. 按实际媒介重写 `generation_contract`。
6. 清空未解决的 `statement_variants`，填写 `review_summary`，把画像和契约都标记为 `reviewed`。

### 6. 应用新任务

应用时只加载已复核画像、新任务事实和少量代表证据。先产出结构或计划，再生成候选；事实来源和风格/方法画像分开，禁止为了“像”而继承原来源事实。

### 7. 同路线复测

候选使用与来源相同的解析和语义检查路线。用 `prepare-evaluation` 把 reviewed profile、候选、当前 objective 和候选复测产物绑定为模板，再完成至少三个独立维度；任一硬约束失败时总体失败，只修改失败维度。

### 8. 运行质量门

```bash
python scripts/kunpeng.py gate init --output <运行目录> --objective "具体目标" --mode <distillation|application> --domains <类型>
python scripts/kunpeng.py gate register --run <运行目录> --type <manifest|cards|profile|candidate|evaluation> --path <产物>
python scripts/kunpeng.py gate check --run <运行目录>
```

蒸馏模式以已复核画像为完成条件；应用模式还必须有非空候选、候选复测证据和通过的验收。

## 完成定义

以下任一情况都不能称为完整蒸馏：只有摘要或统计、只有提示词、事实卡仍是模板、单样本被包装成稳定风格、画像仍是 draft、生成结果未复测，或验证只检查关键词是否出现。
