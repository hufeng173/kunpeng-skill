# UI、交互与动效蒸馏

## 目标

提取界面怎样组织任务、状态和反馈，以及这些选择何时有效。只描述页面长相不是交互蒸馏；静态截图也不能证明完整状态或动效。

## 证据采集

按 `source-routing.md` 实际操作代表性路径，保存前态、动作、过渡和后态的截图/录屏/页面导出与 `capture-log.json`，再运行：

```bash
python scripts/kunpeng.py host-evidence <采集目录> --source-type <website|app|ui> --source-label "名称" --output <证据目录>
```

记录设备/浏览器、视口、登录态、权限、版本和时间。无法触发的状态列为缺口，不补写成事实。

## 任务与页面骨架

- 全局/局部导航、返回路径和当前位置。
- 顶栏、侧栏、工具栏、底栏、浮动操作与主工作区。
- 列表、详情、预览、属性、表单、日志、时间线和阅读区的关系。
- 弹窗、抽屉、菜单、提示、确认和批量操作。
- 3D、Canvas、地图、编辑器、图表、游戏场景和 HUD 的业务角色。

先写用户如何进入、定位、操作、确认、恢复和退出，再判断布局是否支持主任务。区分浏览、创作、监控、交易和游戏等任务类型。

## 状态覆盖

关键功能按适用性检查：

- 初始、加载、空、部分完成、成功、失败、离线和权限不足。
- 默认、悬停、聚焦、按下、选中、禁用和处理中。
- 保存、撤销、重做、确认、取消和离开未保存内容。
- 长任务进度、重试、恢复、日志、通知和错误修复入口。
- 窄屏、触控、键盘、屏幕阅读器和减少动态效果。

事实卡要记录状态转换：`前置状态 + 触发 → 可见反馈 + 状态变化 + 后续操作`。

## 动效

每个动效记录：触发条件、承担的层级/连续性/反馈/品牌功能、时长、延迟、缓动、位移/缩放/透明变化、交错、打断与回退。高频操作应克制；减少动态效果和低性能环境要有降级。

不要从录屏帧率直接断言真实动画参数。能检查代码时用 CSS/JS/动画配置交叉验证；不能时给测量区间和不确定性。

## 特殊工作区

- **3D/Canvas/地图**：镜头、缩放、旋转、选择、命中、加载、性能和普通 DOM 控件如何协同。
- **编辑器/创作工具**：素材、画布、图层、属性、历史、快捷操作、预览和导出如何保持上下文。
- **游戏**：核心循环、输入反馈、HUD、教程、暂停、失败、奖励和重玩；区分世界信息与系统菜单。

## 画像与应用

聚合时区分产品固定规则、任务类型分支、平台规范、品牌表达和单页例外。生成契约必须包含信息架构、关键路径、状态机、布局/组件关系、交互动作、动效、响应式、可访问性、错误恢复和验收步骤。

应用到新产品后，实际运行或预览候选，重复相同任务路径并保存候选证据。仅代码看起来合理或首页截图相似不能通过。
